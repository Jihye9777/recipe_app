# 단계별 근거 보존과 저장 전 누락 검사

상태: 단계 구조화·원문 대조·검토 및 저장 보호를 구현했다. `step-evidence-v1`의 실제 지원 범위와 제한은 README의 단계별 근거 절을 따른다. 합성 예문은 로컬 Gemma로 검사 완료까지 확인했고, 저장 원문 한 건은 사실 추출을 확인하지 못해 검토 대기로 남았다. 원본 DB는 변경하지 않았다. 독립 실행 검증과 로컬 main 병합은 별도 완료 기록으로 남긴다.

## 목표와 범위

사용자가 요청한 개선은 원문의 재료·분량·조리 동작·기구·시간을 분리해 확보하고, 최종 레시피에서 빠지거나 달라진 정보를 저장 전에 발견하는 것이다. 식초 1.5스푼과 전자레인지 1분 30초 사례를 회귀 검사에 포함한다. 특정 영상이나 특정 숫자에 맞춘 예외 규칙은 만들지 않는다.

기존 FastAPI, LangGraph, SQLite, Qdrant, Ollama 구성을 유지한다. 기존 저장 레시피, 작업, 인덱스를 덮어쓰거나 초기화하지 않는다. 신규 패키지·모델 설치, 파일 삭제, 커밋·push는 별도 승인 없이 실행하지 않는다. 기존 자막·Whisper·직접 텍스트 입력을 사용하며 설명란·화면 수집은 이번 변경에 포함하지 않는다.

## 접근 방식

프롬프트만 늘리면 누락을 코드가 발견하지 못하는 문제가 남는다. 반대로 기존 문자열 단계들을 즉시 새 객체 형식으로 교체하면 화면·검색·기존 저장 데이터가 함께 깨질 수 있다.

따라서 기존 `steps: list[str]`를 유지하고, 근거 기반 `step_details`를 추가한다. 원문에서 먼저 사실을 추출하고, 그 사실을 이용해 최종 레시피를 구성한 후 서로 대조한다. 사용자에게 보일 문장은 구조화된 사실에서 만들며, 원문에 없는 값을 채우지 않는다.

## 데이터 형식

`domain.py`에 다음 타입을 추가한다.

- `StepIngredient`: 재료명, 수량, 단위, 정확한 원문 근거. 불명확한 수량·단위는 null이다.
- `CookingStep`: 사용 재료 목록, 조리 동작, 기구 목록, 시간 초 단위 값, 시간의 원문 표현, 정확한 근거 문구.
- `SourceFacts`: 원문에서 확보한 재료·분량과 조리 단계 사실 목록. 최종 레시피 작성 전에 생성하는 별도 중간 결과다.
- `Recipe.step_details`: 순서가 보존된 CookingStep 목록. 과거 저장 레시피와 검토 JSON을 읽을 수 있도록 기본값은 빈 목록이다. 새 자동 추출에서 목록이 빠지면 품질 문제로 취급한다.

예를 들어 원문에 실제로 전자레인지와 가열 시간이 명시됐다면, 해당 단계의 기구는 전자레인지, 시간은 90초, 시간 원문은 1분 30초로 보존한다. 출력에 전자레인지가 없다는 이유로 요리 상식에서 보충하지 않는다.

기존 원문 문자열은 그대로 저장한다. 새 중간 사실과 검사 결과는 체크포인트에 보존하고, 단계별 인용은 `recipe` JSON의 step_details에 저장한다. 기존 SQLite 열을 삭제하거나 기존 행을 재작성하지 않는다.

## 처리 흐름

기존 수집·전처리 다음에 원문 사실 추출을 둔다. 이후 최종 레시피 구조화, 재료 정규화, 원문·사실·최종 결과 대조, 제한된 재검토, 사용자 확인, 저장, 임베딩 순서로 처리한다.

모델 입력에서 시스템 규칙, 원문, 중간 사실, 재검토 피드백을 구분한다. 중간 사실이나 피드백 자체를 원문 인용의 대체 근거로 인정하지 않는다. 최초 원문에 실제 존재하는 인용만 근거로 사용한다.

추출 모델이 중간 사실에서도 누락할 수 있으므로 이 단계를 독립적인 정확도 보증으로 표시하지 않는다. 원문에서 명시적으로 식별할 수 있는 수량·단위, 시간, 기구 표현에 대한 보수적인 코드 검사도 함께 적용한다. 해석이 모호하면 자동 교정하지 않고 검토 사유를 남긴다.

## 저장 전 검사

1. 원문 인용이 실제 입력에 존재하는지 검사한다. 없는 재료·수량·도구·시간을 근거 없이 추가한 결과는 검토 대상으로 보낸다.
2. 중간 사실의 재료와 최종 재료 목록을 비교한다. 식초가 중간 사실에 있는데 최종 목록에서 사라지면 검토한다. 재료명이 모호하면 잘못된 이름을 확정하지 않는다.
3. 명시적 분량을 수량과 단위로 비교한다. ½, 1/2, 0.5는 같은 수량으로 비교할 수 있지만 스푼을 큰술로 추정하거나 단위가 다른 값을 임의 환산하지 않는다.
4. 같은 재료의 원문 분량, 최종 재료 목록 분량, 해당 사용 단계의 분량을 비교한다. 서로 다른 분량을 모두 한 스푼으로 바꾸면 검토한다. 여러 번 나눠 쓰는 경우 부분 사용량과 전체 분량을 구별하며 관계가 불명확하면 검토한다.
5. 같은 조리 행위에 연결된 기구·시간이 구조화 단계와 표시 문장에 보존됐는지 검사한다. 기구가 tools 전체 목록에만 있고 실제 단계에는 빠진 경우도 잡는다. 여러 단계의 기구·시간을 서로 연결해서는 안 된다.
6. 최종 단계에만 등장한 재료, 근거 없는 시간·기구, 실질적 조리 동작 없이 시식 설명만 있는 결과를 검토 대상으로 보낸다.
7. 재검토 후에도 문제가 남으면 기존 LangGraph interrupt로 저장 전에 멈춘다. 검사 실패를 정상 상태로 표시하거나 미상 값을 추측으로 채우지 않는다.

규칙 기반 검사는 지원하는 표현 범위가 한정된다. 임의의 한국어 문장 전체에 대한 완전한 사실 검증을 보장하지 않는다. 처리하지 못한 복잡한 분배·모호한 연결은 검토 대상으로 남긴다.

## 재검토와 사용자 확인

모델 재검토는 기존처럼 최대 1회다. 원문 사실과 검사 사유를 다시 제공한다. 실패하거나 여전히 불일치하면 후보 레시피와 구체적인 사유를 검토 화면에 남긴다.

검토 화면은 누락·충돌한 항목과 근거를 보여주며 기존 JSON 수정·승인 기능을 유지한다. 사용자 승인 저장은 자동 검증 완료와 구별해 user_confirmed로 남긴다. 근거가 없는 정보를 사용자가 추가하더라도 원문에서 추출된 사실로 표기하지 않는다.

과거 체크포인트에는 새 필드가 없을 수 있다. 새 단계 사실이 없다는 이유로 기존 원본을 초기화하지 않는다. 중간 사실을 복원할 수 없는 진행 작업은 검토로 보내거나 명시적인 새 분석을 안내하며 확인 완료로 소급 처리하지 않는다.

## 화면과 저장 호환성

`None`, `null`, 빈 수량·단위는 화면에 `(확인 어려움)`을 한 번 표시한다. 실제 JSON null을 한국어 문구로 저장하거나 적당량으로 바꾸지 않는다. 이 표시 변경은 기존 저장 재료에도 DB 수정 없이 적용한다.

기존 문자열 steps는 계속 제공한다. 새 단계는 구조화된 재료·기구·시간을 빠뜨리지 않도록 문장으로 만들고 화면에 표시한다. 기존 레시피에 step_details가 없으면 현재 저장된 문장을 그대로 보여주며 근거를 자동 생성하지 않는다.

재색인은 저장 레시피의 임베딩을 다시 만드는 기능으로 유지한다. 품질 개선을 적용하기 위한 재추출과 혼동시키지 않는다. 동일 URL 중복 처리도 유지하므로 회귀 평가는 운영 분석 API 대신 별도 평가 저장소에서 실행한다.

## 변경 파일

- `domain.py`: 추가 타입과 보수적인 사실·단계 검사. 필요할 경우 검증 로직만 별도 `recipe_quality.py`로 분리한다.
- `integrations.py`, `prompts/recipe.md`: 원문 사실 추출과 최종 구조화의 입력·출력, 근거 보존 규칙.
- `workflows.py`: 중간 사실 상태와 추출·검토 연결, 체크포인트 호환 처리.
- `storage.py`, `app.js`: 미상 표시와 추가 구조화 데이터의 공개·검토·표시. API의 기존 필드 형식은 유지한다.
- `tests/`, `README.md`: 단계 검사·재개·원본 보존과 사용자 동작 문서.

## 완료 검증

테스트에서 먼저 실패를 재현하고 변경 후 통과를 확인한다.

- None/null/빈 값은 확인 어려움으로 표시하며 원본 값·확인된 분량·단위를 유지한다.
- 식초 1.5스푼 누락과 1스푼으로의 변경을 검출한다. 임의 재료명·분량으로 바꾼 같은 형태의 사례도 검사한다.
- 원문에 전자레인지와 1분 30초가 같은 행위로 명시된 사례에서 기구 누락, 시간 변경, 다른 단계로의 잘못된 연결을 검출한다.
- 큰술과 스푼을 임의로 동등 취급하지 않고 분수·소수만 안전하게 비교한다.
- 근거 없는 재료·분량·기구·시간 추가와 시식 설명뿐인 결과가 자동 저장되지 않는다.
- 재검토에서도 문제가 남으면 review 상태이며 원본 recipes 행은 생성되지 않는다. 사용자 확인 후 재개 동작도 검사한다.
- 과거 레시피·작업 JSON과 기존 화면·검색·삭제 기능이 유지된다. 격리된 SQLite·체크포인트로 원본 보존을 확인한다.
- 현재 Python 및 DOM 테스트를 다시 실행한다. 사용자 저장 DB를 수정하지 않는다.

같은 영상 재검증은 별도 평가 경로에서 실행하고 결과의 근거·남은 검토 사유를 비교한다. 실제 영상 수집이나 모델 호출이 실패하면 그 사실을 보고하며 단위 테스트 결과로 정확도 검증을 대신하지 않는다. 현재 저장 레시피에 새 사실을 자동 덮어쓰지 않는다.
