# 필요한 구간을 보완하는 레시피 수집 설계

상태: 2026-10-28 사용자 설계 승인 및 구현·커밋 요청 확인. 독립 설계 검토에서 구현 계획을 막을 미정 사항은 없었다. 구현 계획은 별도 문서에 작성했으며 계획 확인과 실행 방식 선택 전에는 제품 코드를 수정하지 않는다. 설치·서버 재시작·원격 push는 별도 승인 대상이다.

## 목적과 합의

사용자가 영상을 다시 보지 않고도 따라 요리할 수 있도록 원문에 있는 재료·분량·조리 순서·불 세기·기구·시간을 보존한다. 없는 정보를 일반 요리 지식으로 채우지 않는다. 모든 누락의 제거나 모든 영상의 완전한 이해를 보장하지 않는다.

사용자는 세 접근 중 필요한 구간을 추가 분석하는 방식을 선택했다. 1분 안팎은 성능 목표이며 보장 시간이 아니다. 시작 전에 예상 대기시간을 안내하고 진행 중 현재 단계·지연 사유를 알린다. 1분이 지나도 추가 확인을 계속하며, 덜 분석한 결과를 완료로 위장하지 않는다.

기존 FastAPI·LangGraph·SQLite·Qdrant Local·Ollama와 직접 텍스트 입력을 유지한다. 유료 API·클라우드 추적·yt-dlp는 추가하지 않는다. 모델·패키지를 자동 설치하지 않는다. 실제 처리 속도, 설치 모델의 이미지 지원 및 영상 디코더 사용 가능 여부는 구현 전 확인할 사항이며 현재 확보됐다고 가정하지 않는다.

## 현재 구조와 이번 범위

현재 server.py는 한국어·영어 자막을 공백 문자열로 합치고, 자막 API에 예외가 나야 pytubefix/Whisper로 넘어간다. workflows.py는 수집 언어·출처를 버린다. step-evidence-v1은 확보한 텍스트와 구조화 사실의 불일치를 검사하지만 영상 전체가 수집됐는지는 검사하지 않는다. 같은 영상은 기존 결과를 반환한다.

이번 설계는 단순 프롬프트 수정이 아니라 출처 수집·선택적 화면/음성 보완·검사·작업 진행 정보의 연결이다. 2026-10-18 설계의 출처 보존 방향을 계승하되 저해상도 스토리보드만으로 충분하다는 가정은 사용하지 않는다. 2026-10-22의 단계 구조·승인 해시·저장 직전 검사 보호를 유지하고 여러 출처에 맞게 확장한다.

화면 전면 재디자인, 스마트폰 온디바이스 실행, 사용자 계정, 원격 배포, 기존 레시피의 자동 교체는 범위 밖이다. 기존 데이터·인덱스·체크포인트를 초기화하지 않는다.

## 검토한 접근

| 접근 | 장점 | 제한 | 결정 |
| --- | --- | --- | --- |
| 자막과 설명란만 수집 | 처리량과 구현 부담이 작다 | 화면에만 표시된 조리 정보가 빠진다 | 목표에 부족함 |
| 전체 구간을 간격별로 확인한 뒤 필요한 구간 보완 | 자막 밖의 누락을 찾으면서 추가 분석량을 제한한다 | 샘플 사이의 짧은 장면은 놓칠 수 있다 | 사용자가 선택함 |
| 전체 음성과 촘촘한 화면 분석 | 더 넓은 자료를 확인한다 | 로컬 처리 시간이 길고 완전성은 여전히 보장하지 못한다 | 이번 기본값에서 제외함 |

## 수집과 출처 데이터

sources.py가 수집을 담당하고 domain.py가 버전형 SourceBundle과 Observation을 검증하도록 제안한다. 각 출처에는 ID, 종류, 영상 URL, 수집 방법·언어, 가능한 시작·끝 시각, 원문 텍스트, 수집 성공/빈 결과/실패 상태를 보존한다. 자동 자막 여부와 영상 길이도 기록한다.

Observation은 재료·분량·동작·불 세기·기구·시간, 연결된 출처 ID, 원문 인용 또는 이미지 참조, 구간, 판독 가능 여부, 불확실 사유를 가진다. 출처 종류는 caption, description, speech, frame_text, visual_action, manual로 구분한다.

화면 글씨 전사와 눈으로 본 동작은 구별한다. 모델이 만든 시각 묘사를 실제 자막 인용처럼 취급하지 않는다. 프레임 한 장으로 재료 종류·가열 시간·불 세기를 추정하지 않는다. 동작은 인접 프레임에서 관찰 가능한 범위만 기술하고 재료 정체나 순서가 모호하면 검토 사유로 남긴다. 모델이 보고한 높은 확신 수치만으로 사실을 확정하지 않는다.

SourceBundle은 수집 범위, 읽을 수 없었던 구간, 샘플 시점, 실패·충돌·제한 사유를 포함한다. 빈 설명란과 설명란 요청 실패를 구별한다. 외부 글과 이미지 속 지시는 실행 지시가 아닌 입력 자료다. 이미지 base64와 영상 원본을 레시피 API나 일반 로그에 넣지 않는다.

## 처리 흐름

1. URL·중복·실행 환경을 확인한다. 이미지 모델과 디코더가 준비되지 않았다면 설치하지 않고 화면 확인 불가를 알린다. 처리 가능한 텍스트 근거는 유지하되 전체 수집 성공으로 표시하지 않는다.
2. 타임스탬프를 보존한 자막과 제목·설명란을 수집한다. 자막이 있다는 이유만으로 자료가 충분하다고 판단하지 않는다.
3. 영상 시작·중간·끝을 포함하는 간격별 화면을 확인한다. 자막이 가리키는 구간만 보지 않는다. 스토리보드는 탐색에 쓸 수 있지만 글씨 판독이 불가능하면 원본에 가까운 해상도의 프레임 확보를 시도한다. 필요한 디코더·다운로드 수단이 없으면 그 사실을 보존한다.
4. 출처별 사실을 뽑고 누락 후보를 찾는다. 설명란 재료가 조리 단계에 대응하지 않는 경우, 자막에 조리 동작이 거의 없는 경우, 화면 글씨 판독 불가, 단계 순서의 불연속, 출처별 분량 충돌을 신호로 쓴다. 설명란에는 선택 재료나 다른 요리도 있을 수 있으므로 대응하지 않는 이름을 곧바로 필수 재료로 확정하지 않는다.
5. 시간 정보가 있는 후보는 주변 구간을 더 자세히 확인한다. 설명란처럼 시점이 없는 단서는 전체 탐색 프레임에서 관련 후보를 찾고, 위치를 못 찾으면 넓은 빈 구간부터 제한적으로 보완한다. 모델이 근거 없이 특정 시점을 만들어 선택하게 하지 않는다.
6. 음성 설명이 있고 자막이 부족한 구간은 로컬 Whisper로 보완한다. 자막 API 예외뿐 아니라 내용 부족도 보완 조건이다. 음악뿐인 구간에서는 음성 재시도로 화면 글씨를 복원할 수 없으므로 반복하지 않는다.
7. 새 근거가 생기면 출처 묶음의 새 revision과 사실 스냅샷을 만든다. 각 스냅샷은 수정하지 않는다. 같은 근거를 두고 LLM만 다시 호출하는 repair는 스냅샷을 바꾸지 못한다. 최종 후보는 사용한 revision·모델·검사 버전을 식별한다.
8. 최종 재료와 단계의 출처 대응·누락·모순을 검사한다. 근거가 일치한 값만 표시하고 출처 충돌을 임의 우선순위로 숨기지 않는다. 도구·불 세기·시간·순서도 보존한다. 남은 문제는 사용자 검토로 보낸다.

직접 텍스트 입력은 영상 다운로드나 화면 분석을 강제하지 않는다. 처리한 것은 텍스트라는 범위를 표시한다.

## 분석량과 종료 조건

다음 수치는 사용자 요구가 아니라 무한 분석을 막기 위한 설계 제안이다. 최초 탐색은 최대 12프레임, 추가 확인은 최대 2회이며 전체 이미지 분석은 최대 24프레임으로 제한한다. 영상 길이와 읽을 수 있는 해상도에 맞춰 시점·간격을 선택한다. 샘플 개수는 완전성을 뜻하지 않으며 짧은 장면을 놓칠 수 있음을 기록한다.

기본 전체 처리 상한은 실행 시작부터 10분으로 제안한다. 대기열 시간은 별도다. 다운로드·HTTP·음성·모델 호출은 남은 예산에 맞는 타임아웃과 응답 크기/다운로드 용량 제한을 둔다. 다운로드 용량과 해상도의 구체값은 기존 도구 확인 후 구현 계획에서 정한다. 예산 소진 시 새 보완을 시작하지 않고 확보한 결과를 검토 대기로 보존한다. 사용자 취소도 다음 안전한 중단 지점에서 반영한다. 취소나 시간 초과로 실행 중인 일을 완료로 표시하지 않는다.

근거가 충분하고 충돌이 없으면 자동 검사 통과로 진행할 수 있다. 시각 동작 추론, 읽기 불가, 수집 실패, 불명확한 단계 연결, 해결하지 못한 충돌은 검토가 필요하다. 이미지·음성 수집 자체가 완전히 실패하고 사용할 텍스트도 없으면 작업 실패로 종료한다. 전체 영상 검증 완료라는 상태는 두지 않는다.

## 예상 시간과 진행 정보

기존 jobs 상태 queued/running/review/complete/failed는 유지하고 진행 정보에 elapsed_seconds, 현재 단계, 보완 이유, 예상 남은 시간 범위, 추정 근거 유무, 취소 요청 여부를 추가한다. 대기열 대기와 실제 분석 시간을 구별한다.

예상 시간은 영상 길이, 사용할 분석 종류, 동일 PC·모델의 과거 단계별 처리 기록으로 산출한다. 모델 변경·첫 실행 등 근거가 부족하면 숫자를 확정하지 않고 예상 시간 계산 중임을 알린다. 1분은 목표이며 측정값 없이 고정 카운트다운이나 허위 퍼센트를 표시하지 않는다.

약 1분을 넘으면 추가 분석 중인 사유를 설명하고 갱신 가능한 추정치를 갱신한다. 완료 예정 시각이 지나도 0초를 반복 표시하지 않는다. 핵심 내용은 예상 범위·경과 시간·현재 작업·지연 사유이며 화면 배치와 문구는 기존 디자인 안에서 구현자가 결정한다. 예측 보정 기록에는 처리 시간·분석량·모델 식별만 남기고 개인 레시피 원문은 기록하지 않는다.

## 저장·기존 데이터·재개

SQLite를 원본으로 유지하고 source_bundle과 수집·검사 버전, 작업 진행 메타데이터를 보존형 변경으로 저장한다. Qdrant는 승인해 저장된 레시피의 파생 검색 인덱스다. 실패·중단 시에도 확보한 텍스트 근거·시점·수집 상태를 체크포인트에 보존한다.

현재 step-evidence-v1의 단일 원문 부분 문자열 검사를 여러 출처 ID·시점·인용 검증으로 확장한다. 시각 모델 출력은 원문 문자열 일치만으로 검증됐다고 간주하지 않는다. 사용자 승인은 후보·근거 revision의 조합에 묶고 근거가 바뀌면 재승인을 요구한다. 과거 체크포인트를 새 검사 완료로 소급 표시하지 않는다.

같은 URL에 기존 레시피가 있으면 기존 반환을 유지하되 재분석되지 않았음을 알린다. 이번 변경의 첫 검증은 원본을 건드리지 않는 별도 평가 저장소와 신규 분석이다. 운영 DB에서 기존 레시피를 교체하거나 이력을 관리하는 재분석 기능은 별도 후속 범위이며 기존 행 삭제를 재분석 절차로 안내하지 않는다.

프레임·오디오 임시 자료는 앱 전용 격리 경로에만 보관한다. 자동 정리는 파일 삭제 승인을 별도로 받은 범위에서만 구현한다. 승인 전에는 보관 위치·용량 제한을 명시하고 임의 삭제하지 않는다. 민감한 원문과 이미지가 Git·추적 서비스·일반 로그에 노출되지 않게 한다.

## 안전 경계

메타데이터·영상·이미지 요청은 허용한 YouTube 제공 호스트와 검증된 HTTPS URL로 제한한다. 리다이렉트도 매 단계 확인하고 임의 설명란 URL·사설 IP로 요청하지 않는다. 다운로더에도 같은 주소·크기·시간 정책을 적용한다. 인증 쿠키·토큰 수집, 로그인 우회, 요청 차단 우회는 범위 밖이다. 외부 입력은 JSON/스키마 경계에서 검증하고 화면 출력은 이스케이프한다.

이미지 모델 미지원, 디코더 부재, 네트워크 실패, 요청 차단은 정상적인 실패 조건이다. 추가 패키지·모델이 필요하면 대상과 자원 사용을 설명하고 먼저 승인받는다. 오래 실행된 서버 문제와 별개이므로 실행 코드 버전·모델·검사 버전을 상태 API에서 확인 가능하게 하는 진단 정보를 추가하도록 제안한다. 기존 서버 종료·재시작은 별도 실행 승인 전에는 하지 않는다.

## 검증과 완료 기준

- 설명란에만 있는 재료, 화면에만 있는 분량·불 세기, 빈약한 자동 자막, 음악뿐인 음성, 짧게 지나가는 지시, 서로 다른 출처 분량을 각각 검사한다. 발견하지 못한 정보와 잘못 추가한 정보를 별도로 센다.
- 시간·기구·단계 정보의 출처 연결, 사실 revision 고정, 보완 실패 경고 유지, 예산 소진·취소, 명시적 사용자 승인, 기존 체크포인트 검토를 단위/워크플로/API 검사에 포함한다.
- 예상 시간 근거가 없는 첫 실행, 대기열, 1분 초과, 추정 만료, 긴 작업의 단계 갱신을 검사한다. 실제 화면의 모바일·데스크톱 사용성은 브라우저에서 확인한다.
- 기존 Python/API·DOM·삭제·검색 검사를 유지한다. 임시 SQLite에서 마이그레이션 전후 기존 레시피·원문 보존을 검증한다.
- 사용자 제보 파스타 영상과 기존 비교 대상 영상을 별도 SQLite·체크포인트·Qdrant에서 평가한다. 사람이 확인한 영상 구간·설명란과 재료·분량·순서·기구·시간·불 세기를 대조한다. 평가 근거를 확보하지 못하면 실영상 정확도는 미검증이라고 보고한다.
- 현재 PC에서 단계별 소요 시간, 보완량, 전체 시간, 검토 사유를 측정한다. 1분 목표 달성 여부와 정확도 개선은 별도 결과다. 테스트 통과나 검토 대기를 정확도 향상으로 해석하지 않는다.
- 운영 DB 원본은 평가 전후 읽기 전용으로 비교한다. 신규 승인 결과만 저장하고 모델·설치·서버 상태를 무단 변경하지 않는다.

## 구현 계획에 남긴 결정

사용 가능한 이미지 모델·영상 디코더 확인, 프레임 확보와 부분 음성 처리의 실제 라이브러리 경로, 해상도·다운로드 용량 상한, 예상 시간 보정의 최소 표본 수, 출처 저장 열/테이블의 상세 형태는 구현자가 기존 환경을 확인해 계획에 명시한다. 12/24프레임·2회·10분 제안값은 성능 보장이 아니며 평가에 근거해 조정한다. 조정으로 분석 범위나 개인정보 경계가 달라지면 다시 확인한다.

설계 문서 승인 후 writing-plans로 작업 계획을 작성한다. 문서 작성은 구현·설치·커밋·push 승인으로 해석하지 않는다.
